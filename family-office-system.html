System Architecture

The user interacts with skills via slash commands. Each skill reads from a shared profile/ data store, calls external data sources through a prioritized tool cascade, and writes versioned markdown reports. Memory persists between sessions.

Orchestration Pattern — Parallel Sub-Agents

11 of the 25 skills use the same fan-out pattern: read profile state → spawn N specialist sub-agents in parallel → synthesize their outputs → write a single report. This is the system's core compute primitive.

Why this works. Parallelism gives wall-clock speed (4–6 agents researching at once). Specialization gives depth (each agent focuses narrowly). The synthesizing orchestrator gives coherence (a single voice, single report, no contradictions). The shared profile gives all sub-agents the same grounding.

The --challenge flag adds adversarial review

Any skill producing an investment recommendation supports --challenge, which appends a Devil's Advocate section arguing the opposite position with full conviction. Prevents confirmation bias.

Recreate This System (API-Agnostic Blueprint)

This section is the build guide for another agent. It describes the patterns, not the specific APIs. Substitute the data sources you have access to.

Core principles

PrincipleWhat it means concretely
File-based stateNo databases. All state lives in JSON/CSV/MD files in a versioned directory. Every skill reads and writes plain text. The user can inspect any state with a text editor.
Skills as slash commandsEach agent is a self-contained markdown file with YAML frontmatter (name, description, argument-hint, disable-model-invocation). Invoked via /skill-name. The skill's body is the system prompt.
Profile-first groundingEvery skill MUST read relevant profile files before doing anything else. Never guess household state — read it.
Parallel sub-agents for depthComplex skills fan out to N specialist sub-agents in parallel, then a synthesizing orchestrator merges their findings. 4–6 agents is the sweet spot.
Tool-priority cascadeEach data type has a preferred API. Sub-agents are told explicitly to use the right tool first and treat web search as a last resort for structured data.
Versioned outputsEvery artifact is dated and saved. The directory is the journal — reports are never overwritten.
Standardized recommendation formatAnalysis first, then a fixed structure (Action / Target / Conviction / Size / Risk / Horizon / Invalidation). Makes outputs comparable across time.
Devil's advocate built-in--challenge flag flips the orchestrator into adversarial mode after the primary analysis. Forces both sides.
Date awarenessEvery session opens by confirming today's date. All data is tagged with recency. Stale data is flagged, not silently served.
Idempotent syncThe intake skill (/sync) is rerunnable. Drop files in, run sync, see a diff, accept. No write-once side effects.
